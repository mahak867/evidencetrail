EvidenceTrail MCP server

EvidenceTrail is also a Model Context Protocol server, so Claude Code, Claude Desktop, Gemini CLI or any MCP agent can investigate incidents with the same read-only tools and evidence gate. It never injects faults or runs actions.

Connect from Claude Code
claude mcp add evidencetrail -- python -m evidencetrail.mcp_server
Gemini CLI (~/.gemini/settings.json)
{"mcpServers": {"evidencetrail": {"command": "python", "args": ["-m", "evidencetrail.mcp_server"]}}}
Remote (streamable HTTP)
python -m evidencetrail.mcp_server --http 8765

Tools exposed

get_service_healtherror ratio and p95 vs baseline
get_suspectscall-graph-ranked anomalous services
get_logsgrouped, redacted, with evidence IDs
get_metrictime series for one metric
get_error_traceschain of failing spans
get_recent_changesdeploys and config changes
investigatefull Gemini investigation + evidence gate

All tools are annotated read-only. Suggested actions are returned, never executed.

Google ADK engine

The investigation can run on Google's Agent Development Kit: an ADK LlmAgent with Gemini and EvidenceTrail's tools runs the agent loop, then the same evidence gate and safety policy verify the result. ADK proposes, EvidenceTrail verifies.

ENGINE=adk uvicorn evidencetrail.server:app --port 8080

Both engines are scored on the same faults; see the Scorecard.

Guarantees in every integration

  • Every claim must cite evidence fetched in this investigation
  • Secrets, card numbers and emails redacted before any model sees logs
  • Read-only telemetry; action risk set by policy, not the model
  • Any change needs a named human approval and is audit-logged
